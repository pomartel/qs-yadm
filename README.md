# qs-yadm — Omarchy yadm Plugin

qs-yadm puts your [yadm](https://yadm.io/) worktree in the
[Omarchy](https://omarchy.org/) bar. It shows a compact `Y` and the number of
tracked files that have changed, then provides a native Quickshell panel for
reviewing, committing, pushing, and synchronizing those dotfiles.

## Features

- Icon-only bar entry when clean; `Y <count>` when tracked files have changed
- Per-file additions and deletions in a Dropbox-style panel
- Theme-aware focused diff viewer with two lines of surrounding context
- Ahead and behind commit counts relative to the upstream branch
- One-click background commits with short commit subjects generated by the
  configured Omarchy agent
- Ctrl-click multi-selection followed by Enter to commit several files together
- Optimistic removal from the list while commits run in the background
- Pull/rebase/autostash from `origin` every minute
- Automatic Codex-assisted conflict resolution
- An urgent `!` for pull, push, commit, agent, and unresolved-conflict failures
- Keyboard and shell IPC control

Only modified, deleted, renamed, or staged **tracked** files are shown. The
large set of unrelated untracked files normally present under `$HOME` is
deliberately ignored.

## Requirements

- Omarchy 4 or newer
- yadm with an `origin` remote
- Codex selected as the Omarchy default agent (`omarchy default agent codex`)

The plugin checks the configured default before each agent job. Other Omarchy
agents currently produce a visible unsupported-agent error instead of silently
falling back to Codex.

## Installation

```bash
omarchy plugin add https://github.com/pomartel/qs-yadm.git --enable
```

To place it after Todoist:

```bash
omarchy plugin enable qs-yadm --section right --after io.github.aryan-techie.todoist
```

Optional Hyprland binding:

```lua
o.bind("SUPER + CTRL + Y", "Yadm", "omarchy-shell shell toggle qs-yadm")
```

## Controls

| Input | Action |
| --- | --- |
| Left-click bar icon | Open or close the panel |
| Middle-click bar icon | Pull immediately |
| Left-click file | Commit that file and push in the background |
| Left-click checkbox | Toggle that file in the batch selection |
| Ctrl + left-click files | Toggle batch selection |
| Space | Toggle the focused file in the batch selection |
| Enter | Commit selected files together, or commit the focused file |
| Right-click file / `d` | Open its diff viewer |
| `o` | Open the focused file in the Omarchy default editor |
| `x` | Discard the focused file's changes after saving a recovery patch |
| Up / Down | Move through changed files |
| Right | Open the focused file's diff |
| Left | Return from the diff to the file list |
| `r` | Pull and refresh |
| Escape | Leave the diff viewer or close the panel |

The panel can also be controlled through shell IPC:

```bash
omarchy-shell shell toggle qs-yadm
omarchy-shell qs-yadm refresh
omarchy-shell qs-yadm sync
```

## How synchronization works

Every minute, qs-yadm runs the equivalent of:

```bash
yadm pull --rebase --autostash origin "$(yadm branch --show-current)"
```

For HTTP(S) and standard SSH remotes, qs-yadm first checks whether the repository
is publicly readable over credential-free HTTP(S). Public repositories are pulled
anonymously without changing the configured `origin`; private repositories keep
using the origin's configured SSH key or credential helper.

Repository-changing jobs share a lock, so pulls cannot race commits or pushes.
When a pull enters a rebase or autostash conflict, the plugin asks Codex to
resolve only the conflicted yadm files and validates that the repository no
longer has unmerged paths. If it cannot finish safely, the repository state is
left available for inspection and the bar displays `!`.

## Privacy and safety

Commit-message generation sends the selected unified diff to the configured
Codex service. Automatic conflict resolution gives Codex workspace-write access
to `$HOME` because yadm's worktree is the home directory. Do not use these
features for dotfiles whose contents you do not want processed by your agent
provider.

The plugin uses `yadm commit --only` so a one-file commit does not accidentally
include unrelated staged files. Files are re-read when their serialized job
starts, so a file edited after clicking is committed at its latest state.

Transient errors and lock files live in:

```text
~/.local/state/omarchy/qs-yadm/
```

Before `x` restores a file to `HEAD`, its complete binary-capable diff is saved
with mode `0600` under `~/.local/state/omarchy/qs-yadm/discarded/`. A discarded
change can be recovered with `yadm apply /path/to/the.patch`.

## Troubleshooting

Inspect the current backend state directly:

```bash
python3 ~/.config/omarchy/plugins/qs-yadm/backend.py status | jq
```

Retry synchronization with:

```bash
omarchy-shell qs-yadm sync
```

If `!` reports an unsupported agent, select Codex with
`omarchy default agent codex`. Authentication, network, or remote permission
errors remain visible until a later operation succeeds.

## Updating and removal

```bash
omarchy plugin update qs-yadm
omarchy plugin remove qs-yadm
```

Remove any corresponding `SUPER + CTRL + Y` entry from
`~/.config/hypr/bindings.lua` when uninstalling.

## Development

The plugin consists of `Panel.qml`, the JSON-speaking `backend.py`, and its
manifest. Validate it with:

```bash
omarchy plugin validate .
qmllint -I /usr/share/omarchy/shell Panel.qml
python3 -m unittest discover -s tests -v
```

Pull requests and issue reports are welcome.
